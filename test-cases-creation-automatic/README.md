# Test Data Generation and Spreadsheet Validation (Case Study)

> Sanitized example for portfolio demonstration. No real ticket data, designs, prompts, data, or screenshots are included. All examples are fictional.

## Business Problem

QA needs realistic, safe test data and well-structured test cases quickly, without copying production data or hand-building large datasets for every workflow.

## QA Challenge

- Produce realistic synthetic test data for QA and workflow testing
- Keep generated data free of any real customer or production information
- Validate spreadsheet inputs and outputs used in QA workflows
- Turn requirements into structured, review-ready test cases

## Approach

A documented workflow covering two related QA needs:

- **Test data generation** — produce fictional, synthetic datasets (using fictional identifiers such as `Customer Alpha`, `Vehicle-001`, `Order DEMO-1001`) for performance and workflow testing
- **Spreadsheet validation** — check structure, required fields, and consistency of spreadsheet inputs and outputs used in QA

For the AI-assisted test design workflow (requirement to approved test case with mandatory human review), see [`../case-studies/ai-assisted-test-design.md`](../case-studies/ai-assisted-test-design.md).

## QA Value

- Removes dependence on production data for testing
- Speeds up creation of realistic, safe datasets
- Catches spreadsheet structure issues before they affect QA results

## Limitations

- This is a workflow concept, not a published tool
- Generated data is fictional and intentionally non-production
